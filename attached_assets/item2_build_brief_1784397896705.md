## Goal
Turn the single "Shipping Address" step into two required sections, Billing first
then Shipping, with a "Shipping same as billing" checkbox. Make the order carry a
real billing address so Authorize.net has a billing ZIP to read. Both addresses
are required for every order, guest and signed-in. This brief does NOT add the
save-to-account button and does NOT add any address-dedup enforcement. Those are
Item 3. Do not build them here.

## The model (build exactly this, no more)
- Two labeled sections at checkout: Billing first, then Shipping.
- A "Shipping same as billing" checkbox. Default CHECKED. When checked, the
  shipping section is filled from billing (either visually mirrored or hidden and
  copied on submit, your call, but the submitted shipping values must equal the
  billing values). When unchecked, the customer fills shipping separately.
- Both billing and shipping must be complete before the order can be placed. If
  either is incomplete, the Place Order button stays disabled.
- Guest: types billing, and types shipping (or leaves the checkbox checked). No
  saved addresses (the backend already forbids guests from saved addresses).
- Signed-in customer: billing and shipping are prefilled from their saved billing
  and shipping addresses if those exist. They may still edit inline. A brand-new
  signed-in customer with nothing saved types both, same as a guest.

### The change
1. Restructure the address area into two sections: a Billing section
   (heading "Billing Address") and a Shipping section (heading "Shipping
   Address"), Billing first. Each section supports the same input set the current
   inline form has, and for signed-in customers each section can prefill from the
   customer's saved address of that type.
   - Signed-in prefill: the account addresses list already returns `type` on every
     address (recon confirms `serializeAddress` includes `type`). Use the
     customer's billing-type address to prefill Billing and their shipping-type
     address to prefill Shipping. If a type is missing, that section starts empty.
   - Keep the existing default-select behavior sensible, but it now applies
     per section and per type rather than one global `selectedId`. You may replace
     the single `selectedId` model with per-section state if that is cleaner.
     Whatever you do, a signed-in customer must never be dropped onto a broken or
     empty selection when they have a saved address of that type.
2. Add the "Shipping same as billing" checkbox, default checked. When checked, the
   submitted shipping address equals the billing address. When unchecked, shipping
   is entered separately.
3. Replace `addressComplete` so it requires BOTH a complete billing address AND a
   complete shipping address (street1, city, state, zip non-empty on each; when
   the checkbox is checked, shipping inherits billing and is complete iff billing
   is). The Place Order button stays disabled until both are complete.
4. Change the order payload so it sends a real billing address, not
   `billingSameAsShipping: true`:
   - Always send the shipping address (as a saved `shippingAddressId` for a
     signed-in customer using a saved shipping address, or an inline
     `shippingAddress` object otherwise), exactly as today.
   - Always send billing: either `billingSameAsShipping: true` WHEN the checkbox is
     checked (backend already copies shipping into billing in that case), OR
     `billingSameAsShipping: false` plus a `billingAddress` object (or a saved
     `billingAddressId` for a signed-in customer using a saved billing address)
     when the checkbox is unchecked.
   - Do NOT add `saveShippingAddress` or any save-to-account field. That is Item 3.
5. Leave `billingAddressOptions={{ show: false, required: false }}` as is. We are
   collecting billing in our own form, not in the Authorize.net popup. Do not turn
   the popup billing collection on.
