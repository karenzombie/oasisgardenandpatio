## Question 1 — Canonical policy: Option C, spelled out precisely

Single-facet list URLs are indexable and canonical to themselves (cleaned);
pagination collapses to the facet; multi-facet collapses to base.

Exact rules:

1. **Bare `/shop`** (no params): canonical to `/shop`.
2. **Single facet** (exactly one of `material`, `category`, `manufacturer`):
   canonical to that clean single-facet URL, e.g. `/shop?material=mgp`. This URL
   is indexable.
3. **Page param handling:** ALWAYS strip `page` from the canonical, including
   `page=1`. So:
   - `/shop?material=mgp&page=3` → canonical `/shop?material=mgp`
   - `/shop?material=mgp&page=1` → canonical `/shop?material=mgp`
   The point: `/shop?material=mgp` and `/shop?material=mgp&page=1` must not become
   two indexable versions of the same page.
4. **Multi-facet** (two or more of material/category/manufacturer together):
   canonical to base `/shop`. Do not index the combination.
5. Ignore unknown/tracking params for canonical purposes (do not let them create
   distinct canonicals).

Title/description still describe the actual facet the user is on (so a single
facet page reads "MGP Outdoor Patio Furniture | ..."), but the canonical follows
the rules above. Do not emit `noindex` on these; the canonical does the
consolidation.

## Question 2 — Manufacturer pages: yes, include them in Gate 3

Add `/manufacturers/:slug` (or the actual public route) to the API server path
allowlist and enrich them. Brand queries ("Hanamint patio furniture") are
high-value, and you already have the manufacturer data loaded.

- Title: manufacturer name + descriptive suffix, e.g. "Hanamint Patio Furniture
  | Oasis Garden & Patio".
- Description: from the manufacturer's own fields (name, and description if one
  exists); else a simple template. Same no-fabrication rule.
- Canonical: the clean manufacturer URL.
- OG tags: same set (og:type can be "website" for these list pages).
- Keep the allowlist discipline: add only this explicit public pattern; do not
  broaden to a blocklist.
