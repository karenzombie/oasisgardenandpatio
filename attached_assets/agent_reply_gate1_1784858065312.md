## 1. Architecture: proceed with Option A, with two adjustments

Yes, Option A (a small server that injects head tags into the first HTTP
response). B and C do not meet the goal. Build it with these two adjustments:

- **Reuse the existing Express API server; do not stand up a new one.** It
  already has DB access and the `by-slug` query the injector needs. Route HTML
  document requests through it while keeping static assets (JS, CSS, images,
  fonts, favicon, manifest) on the fast static path. Evaluate this concretely and
  report how you will split document vs asset requests. If reusing the Express
  server is genuinely not workable, STOP and explain why before creating a
  separate process.
- **Cache the injected metadata per route** (per product slug, per category, per
  manufacturer, per filter) with a TTL or an invalidation hook, so a page hit
  does not trigger a fresh DB lookup every time. Report the cache approach and
  TTL at check-in.

**Reliability requirements (non-negotiable, because this replaces a
near-unbreakable static serve with a running process):**

- The injector only builds `<head>` tags. It must never render the page body and
  never touch cart, checkout, pricing, or the Authorize.net path.
- **Static fallback:** if the metadata lookup fails, errors, or times out, serve
  the plain unmodified `index.html` and let the SPA render normally. A failed or
  slow lookup must NEVER block or break the page. Confirm this fallback works by
  testing it (e.g. simulate a lookup failure) at verification.
- Build and verify entirely in dev first.

## 2. noindex rule: use catalog_visible / is_active, NOT availableOnline

Do not treat `availableOnline=false` as hidden. Those products are in inquiry
mode and are intentionally still shown on the storefront; we want them indexed so
customers can find them and then inquire.

The real hide flag is `catalog_visible`. The rule:

- Emit `<meta name="robots" content="noindex">` and NO enriched metadata (generic
  title only) when `catalog_visible = false` OR `is_active = false`.
- Otherwise (publicly visible), inject the full enriched metadata.

The `by-slug` response does not currently return `catalog_visible`. **Add
`catalog_visible` to the `by-slug` response** so the injector can apply this rule.
That is the only API change authorized here: adding one existing column to an
existing read response. Do not change any other field, query, or endpoint.
