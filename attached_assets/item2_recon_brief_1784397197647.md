## Why
Item 2 restructures the checkout address area into a required Billing section and a
required Shipping section with a "shipping same as billing" checkbox, makes the
checkout backend persist both addresses, and lets a signed-in customer save what
they type at checkout back to their account. Before any of that is written, we
need an accurate map.

## The locked model this recon is serving (context only, do not build yet)
- Every order captures both a billing and a shipping address. Both required. The
  order cannot complete with either blank, because Authorize.net reads the billing
  address and its ZIP cannot be empty.
- Checkout shows two labeled sections, Billing first then Shipping, with a
  "shipping same as billing" checkbox that copies billing into shipping. Billing
  is primary.
- Guests type both (or use the checkbox). Signed-in customers get saved values
  prefilled, can type inline, and get a "save to my account" option that is
  checked by default.
- Every customer has at most one billing address record and one shipping address
  record. Saving from checkout or from My Account upserts those single rows in
  place, never creating a second of the same type. (Enforcement itself is Item 3;
  Item 2 only needs to know the write path exists.)
